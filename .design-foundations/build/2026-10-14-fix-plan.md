## Commit 2: keyboard: explorer roving focus, Right/Left, auth dialog (defects 4, 5, 6)

### 4. Explorer: one roving Tab stop (R4)
Root cause: every `button[data-nav]` (table name, expander, column buttons) keeps the default tabindex, so each is a Tab stop (14+ before the worksheet).

Exact change (`index.html`, explorer section near line ~1346, plus `tableItem` near line ~1284):
```
let explorerStop = null;
function roveExplorer(focused) {
  const all = [...$('explorer').querySelectorAll('button[data-nav]')];
  if (focused) explorerStop = focused;
  if (!all.includes(explorerStop)) explorerStop = all.find(b => b.offsetParent) || all[0];
  for (const b of all) b.tabIndex = b === explorerStop ? 0 : -1;
}
$('explorer').addEventListener('focusin', e => { const t = e.target.closest('button[data-nav]'); if (t) roveExplorer(t); });
```
- Call `roveExplorer()` at the end of `renderTableLists()` (filter input re-renders).
- Call `roveExplorer()` after `cols.replaceChildren(...)` in the `toggle` of `tableItem` (new column buttons are created with default tabindex).
- The search box stays a normal Tab stop before the list.

Result: Tab from Search reaches one explorer stop, then the worksheet region. Up/Down still move (existing handler). Roving stop survives filter and expand.

### 5. Explorer: Right/Left on expander and column rows (R4: "Right/Left expands/collapses columns")
Exact change (`index.html`, keydown handler near line ~1346-1356; replace the `.tn` check):
- Right on a table name or expander (not a column): if collapsed, `tli._toggle(true)`; if already expanded, focus its first column button.
- Left on a table name or expander: if expanded, `tli._toggle(false)`.
- Left on a column: focus the table's name button (`.tn`), then `tli._toggle(false)` (focus first, otherwise the focused column is hidden).
- Where `tli` = `t.closest('.cols') ? t.closest('.cols').parentElement : t.closest('li')`.
- Keep `preventDefault()` on handled keys. Right on a column does nothing (no deeper level).
Simplification allowed: the "Right on expanded table moves to first column" branch is optional. Include it only if it stays a few lines.

Result: arrow keys work on all three row kinds; Left on a column returns to its table and collapses it.

### 6. Auth dialog Tab order (R15)
Root cause: the dialog opens with focus on Username (spec), so a forward Tab walk goes Password, Show, submit, then wraps to Close, Log in, Sign up. The mode tabs are reached last. A native modal wrap cannot be fixed by moving DOM alone, since reading order already places Close and tabs before the fields.

Recommended exact change (`index.html` lines ~527-547, plus the mode handler):
- Keep DOM order (heading and Close, mode tablist, fields, submit). Do not move Username focus.
- Make the segmented control a real tablist with roving tabindex: only the selected mode tab has `tabIndex = 0`, the other has `-1`. Set this wherever `aria-selected` is changed for `data-mode` buttons (`grep data-mode` in `index.html`). Add Left/Right keydown on the tablist that switches mode and moves focus.
- Result: forward Tab from Username is Password, Show, submit, Close, then the selected mode tab, then Username. Sign up is reached with Right Arrow from Log in (one Tab stop instead of two).
- Trade-off to tell the critic: the wrap is still native. The spec's intent (mode switch reachable without going through submit) is met by Shift+Tab from Username (reaches the mode tab directly) and by Arrow keys. If the developer finds this insufficient, the alternative is to change R15 to focus the selected mode tab on open. Do not do that without a spec change.
